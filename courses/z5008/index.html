Big Data Lab

A hands-on laboratory course covering the full modern big data engineering stack. Students build end-to-end pipelines using Apache Spark, Delta Lake, Apache Iceberg, Kafka, and MLflow, progressing from lakehouse foundations through real-time streaming to distributed machine learning and MLOps. Every session is a two-hour-forty-minute lab with working code as the deliverable. Even Semester 2026.

Learning Outcomes

On successful completion, a student will be able to:

  1. 1 Deploy a Docker-based big data environment and run end-to-end PySpark jobs, explaining the Spark execution model, DAG stages, and Spark UI metrics.
  2. 2 Build and manage Delta Lake and Apache Iceberg tables with ACID transactions, time travel, schema evolution, and partition evolution.
  3. 3 Write complex PySpark SQL queries and window functions over large datasets, and profile and fix performance bottlenecks using Adaptive Query Execution.
  4. 4 Orchestrate batch Spark workloads using Apache Airflow DAGs and Dagster pipelines with dependency management and scheduling.
  5. 5 Build real-time streaming pipelines with Apache Kafka and Spark Structured Streaming, implementing watermarks, window aggregations, and exactly-once semantics.
  6. 6 Create live observability dashboards with Grafana and Prometheus, and deploy interactive data applications with Streamlit.
  7. 7 Train and tune distributed ML models with Spark MLlib and Ray, tracking experiments and registering models with MLflow.
  8. 8 Package and deploy ML models as production REST APIs using BentoML and Docker, with Prometheus monitoring and OpenLineage data lineage.

Policies

Attendance

Attendance is mandatory at all lab sessions. Lab work is submitted before the session ends; you cannot replicate the hands-on practice outside the structured session.

Late work

Late work is not accepted. Deadlines are fixed and announced in advance; submit what you have by the deadline. No extensions.

Academic integrity

Discussing approaches is encouraged; submitting another student's code is not. Every notebook you submit must reflect your own work, which you can explain and extend.

Use of AI tools

AI assistants may be used to explain API behaviour and debug errors. Solutions generated by AI and submitted without understanding are a violation of academic integrity. Declare any material AI contribution in a notebook header cell.
