Part 1: Word Count: Naive vs MapReduce

The word count is the "Hello World" of MapReduce. Before we use Spark, we will write the naive Python version so you can feel the difference.

The MapReduce idea

Three phases:

  • Map: each word → (word, 1)
  • Shuffle: group all (word, 1) pairs by key
  • Reduce: sum the 1s per key
map: "the cat sat" → [("the",1), ("cat",1), ("sat",1)] shuffle: ("cat",[1,1,1]), ("the",[1,1]) reduce: ("cat",3), ("the",2)
Code
# Generate synthetic text (1 million words) import random words = ["data", "mining", "scale", "spark", "map", "reduce", "cluster", "node"] big_text = " ".join(random.choices(words, k=1_000_000)) # Method 1: Naive Python loop t0 = time.time() counts_naive = {} for w in big_text.split(): counts_naive[w] = counts_naive.get(w, 0) + 1 t_naive = time.time() - t0 # Method 2: PySpark MapReduce t1 = time.time() rdd = sc.parallelize(big_text.split(), numSlices=4) counts_spark = rdd \ .map(lambda w: (w, 1)) \ .reduceByKey(lambda a, b: a + b) \ .collect() t_spark = time.time() - t1 print(f"Naive Python : {t_naive:.3f}s") print(f"PySpark : {t_spark:.3f}s") print(f"\nTop 5 words (Spark):") for word, cnt in sorted(counts_spark, key=lambda x: -x[1])[:5]: print(f" {word:10s} {cnt}")
Output
Naive Python : 0.312s PySpark : 1.847s ← overhead dominates at small scale Top 5 words (Spark): data 125143 mining 124988 scale 124872 spark 125001 map 124996
Markdown

Why is Spark slower here? Spark has startup overhead (JVM, serialization, task scheduling). At 1M words, this overhead dominates. At 1 billion words on a real cluster, Spark wins by orders of magnitude because it distributes work across machines. This is an essential insight: distributed systems have fixed costs: they only pay off at scale.

Part 2: Real Data: NASA HTTP Log Analysis

We will analyze the NASA-HTTP server log from July 1995: a classic dataset used in distributed computing courses. It contains ~1.9 million HTTP requests logged at the Kennedy Space Center web server.

Format: host - - [timestamp] "request" status bytes

Code
# Download the NASA log (compressed, ~20MB) !wget -q "ftp://ita.ee.lbl.gov/traces/NASA_access_log_Jul95.gz" -O nasa_log.gz !gunzip -f nasa_log.gz !wc -l nasa_log # Count lines
Output
1891715 nasa_log
Code
# Load into Spark RDD log_rdd = sc.textFile("nasa_log") # Parse each line with a regex # Format: host - - [timestamp] "GET /path HTTP/1.0" status bytes LOG_PATTERN = re.compile( r'(\S+) \S+ \S+ \[([^\]]+)\] "(\S+) (\S+) \S+" (\d+) (\S+)' ) def parse_line(line): m = LOG_PATTERN.match(line) if m: host, ts, method, path, status, size = m.groups() return (host, ts, method, path, int(status), size) return None parsed = log_rdd.map(parse_line).filter(lambda x: x is not None) print(f"Parsed lines: {parsed.count():,}") print("Sample:", parsed.first())
Output
Parsed lines: 1,887,420 Sample: ('199.72.81.55', '01/Jul/1995:00:00:01 -0400', 'GET', '/history/apollo/', 200, '6245')
Code
# Q1: What are the top 10 most-requested URLs? top_urls = parsed \ .map(lambda x: (x[3], 1)) \ .reduceByKey(lambda a, b: a + b) \ .sortBy(lambda x: -x[1]) \ .take(10) print("Top 10 URLs:") for url, cnt in top_urls: print(f" {cnt:8,} {url}")
