Task 1 — Class Design (7 marks)

Task 1a — 4 marks

Implement a BankAccount class

Create a class BankAccount with:

  • A private attribute _balance initialized from the constructor argument (default 0)
  • Method deposit(amount) that adds amount to the balance (raise ValueError if amount ≤ 0)
  • Method withdraw(amount) that subtracts amount (raise ValueError if amount ≤ 0 or if it would cause overdraft)
  • Property balance that returns the current balance (read-only)
  • __str__ that returns "BankAccount(balance=X)" where X is the balance

4 marks: 1 per correct method/property; 1 for both error cases handled

Task 1b — 3 marks

Write test cases

Write three assert-based test cases that verify your BankAccount implementation. At least one test must check that a ValueError is raised correctly (use a try/except block).

3 marks: 1 per valid, passing test case

Task 2 — Inheritance and Polymorphism (8 marks)

Task 2 — 8 marks

Design an animal hierarchy

Create a base class Animal with:

  • Constructor that accepts name (string) and age (int)
  • Method speak() that returns "..." (base default)
  • __str__ that returns "Animal(name, age)"
Then create subclasses Dog, Cat, and Parrot, each overriding speak() to return an appropriate sound string.

Finally, write a function chorus(animals) that accepts a list of Animal objects and returns a list of strings, each formatted as "[name] says: [sound]". Demonstrate it works with a mixed list containing at least one of each animal type.

8 marks: 2 for base class, 1 per subclass (3), 2 for chorus function and correct output

Task 3 — Operator Overloading (5 marks)

Task 3 — 5 marks

Implement a Vector2D class

Create a class Vector2D(x, y) that supports:

  • __add__: vector addition (returns a new Vector2D)
  • __sub__: vector subtraction (returns a new Vector2D)
  • __mul__: scalar multiplication, where the scalar is a number on the right side
  • __eq__: equality check
  • __repr__: returns "Vector2D(x, y)"
Verify with: assert Vector2D(1,2) + Vector2D(3,4) == Vector2D(4,6)

5 marks: 1 per dunder method

Task 4 — Industry System Design (10 marks)

MTech only

This section does not require code. Write clear, structured prose. Diagrams drawn on paper may be described in text.

Task 4a — 4 marks

OOP Design Critique: Banking System

Consider the BankAccount class you implemented in Task 1. A junior engineer on your team proposes the following extension: "We should create subclasses SavingsAccount and LoanAccount that inherit from BankAccount, and override withdraw() to enforce savings rules and loan repayment schedules."

Answer both of the following:

  1. Identify two concrete problems that would arise from this inheritance design as the system scales to support 20+ account types with overlapping rules (e.g., joint accounts, sweep accounts, fixed deposits).
  2. Propose an alternative design using composition or strategy pattern that avoids these problems. Name the classes/interfaces you would introduce and explain how they interact (2–4 sentences each).

4 marks: 1 per correctly identified problem + 1 per concrete alternative design element

Task 4b — 3 marks

Memory and Performance Trade-offs

A financial analytics platform stores 10 million Transaction objects in memory. Each object currently has 12 attributes (timestamp, amount, currency, sender_id, receiver_id, status, type, region, channel, fee, reference_code, metadata_dict).

The CTO tells you that memory usage is 40% above budget. Describe three distinct OOP or Python-level techniques you would apply to reduce memory footprint. For each, state: (a) what you would change, (b) why it reduces memory, and (c) any trade-off or limitation.

3 marks: 1 per complete technique (change + reason + limitation)

Task 4c — 3 marks

Concurrency Safety in OOP

Two threads simultaneously call withdraw(500) on the same BankAccount object when the balance is 800. Without any locking mechanism, explain:

  1. Exactly what sequence of operations can lead to the balance going negative (write out the interleaved operation sequence step by step)
  2. One OOP-level design change you would make to BankAccount to make it thread-safe, using Python's standard library
  3. Why Python's Global Interpreter Lock (GIL) does not protect against this specific race condition

3 marks: 1 per question answered correctly and completely
