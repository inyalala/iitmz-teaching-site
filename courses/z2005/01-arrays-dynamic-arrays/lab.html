Lab 2 — Arrays and Dynamic Arrays

Before you start

Clone the assignment repository from GitHub Classroom (link on the course page). Do all work there, not in a scratch file — the autograder runs against that repository’s structure.

Part A (20 min) — Warm-up: address arithmetic by hand

Using the address formula from Lecture 1, answer these on paper before touching a keyboard:

  • An array of 4-byte ints has base address 5000. What address holds index 12?
  • A 5×5 grid of 8-byte doubles, base address 0, row-major. What address holds grid[3][4]?
  • Then verify both answers by writing a two-line Python function that computes them.

Part B (60 min) — Build DynamicArray from scratch

Implement a DynamicArray class that behaves like a tiny version of Python’s list, without using list.append internally:

  • DynamicArray() — starts with capacity 1, length 0, backed by a fixed-size Python array created via [None] * capacity (using a plain list only as “raw memory” — you may not call .append on it).
  • append(x) — inserts at the end. When capacity is full, allocate a new backing array of double the capacity, copy every element across, then insert.
  • __getitem__(i) — return the element at index i, raising IndexError if i >= length.
  • __len__() — returns the current length (not capacity).
  • capacity — expose the current backing array’s size as an attribute.

Instrument your append to print "RESIZE: capacity X -> Y" every time a resize happens. Run 20 appends and confirm the resize points match the doubling sequence traced in Lecture 2 (1, 2, 4, 8, 16).

Part C (20 min) — Challenge: measure the cost yourself

Using time.perf_counter, measure and plot (or tabulate) the total time to append 10,000 elements to your DynamicArray versus the total time to insert 10,000 elements at index 0 of a plain Python list using list.insert(0, x). Confirm the shape of the timing matches Lecture 4’s claim: appending stays roughly flat per element, inserting at the front gets worse as the list grows.

MTech addition

Add a shrink behavior to your DynamicArray: when pop() is called and the length falls to one quarter of capacity, halve the capacity (never below 1) and copy elements into a new, smaller backing array. Write three to five sentences justifying why “shrink at one quarter full” is used instead of “shrink at one half full” — connect your answer to the amortized analysis from Lecture 3.

On Your Own (Optional, Ungraded)

This part is optional and ungraded. It is not submitted, not part of the autograder, and not assessed in any way — it exists purely as extra practice if you want to go further with this week’s material after the graded lab tasks are done. There is no deadline attached to it.

Add an insert(i, x) method to your DynamicArray that inserts x at index i, shifting every element from index i onward one position to the right (growing the backing array first if needed). For example, if the array holds [1, 2, 4], insert(2, 3) should leave it as [1, 2, 3, 4]. State the worst-case time complexity of a single call to insert.
