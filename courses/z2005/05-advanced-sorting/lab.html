Lab 6 — Advanced Sorting

Before you start

Clone the assignment repository from GitHub Classroom (link on the course page). Do all work there, not in a scratch file — the autograder runs against that repository’s structure.

Part A (20 min) — Warm-up: merge sort, instrumented

Implement merge_sort and merge exactly as in Lecture 1, instrumented to count comparisons. Run it on random arrays of size 100, 200, and 400, and confirm the comparison count roughly follows \(n \log_2 n\) (within a reasonable constant factor) at each size.

Part B (60 min) — Quicksort, both pivot strategies, benchmarked

Implement quicksort with the Lomuto partition scheme from Lecture 2, using the last element as pivot. Then implement a second version using a randomized pivot (swap a random element into the last position before partitioning). Benchmark both versions on:

  • 1,000 random integers
  • 1,000 already-sorted integers
  • 1,000 reverse-sorted integers

Report timings for all six runs (2 versions × 3 input types) in a table, and explain the pattern you observe, connecting it explicitly to Lecture 2’s worst-case analysis.

Part C (20 min) — Challenge: hybrid sort

Implement a hybrid sort that uses quicksort (randomized pivot) for subarrays larger than 16 elements, and switches to insertion_sort (Week 5 Lecture 2) for subarrays of 16 or fewer. Benchmark it against plain quicksort and Python’s built-in sorted() on a 100,000-element random array, reporting all three timings.

MTech addition

Building on Week 6 Lecture 4’s leaderboard case study, implement a Leaderboard class backed by counting sort (for bulk load, scores 0-10,000) plus a plain Python list kept re-sorted after every update (a deliberately naive placeholder for the “maintained structure” Weeks 7-8 will properly implement). Instrument it to count total comparisons across 1,000 simulated score updates, and write two to three sentences on what a properly maintained tree or heap structure would save, quantitatively, over this placeholder.

On Your Own (Optional, Ungraded)

This part is optional and ungraded. It is not submitted, not part of the autograder, and not assessed in any way — it exists purely as extra practice if you want to go further with this week’s material after the graded lab tasks are done. There is no deadline attached to it.

Implement a three-way partitioning ("Dutch national flag") quicksort variant that groups elements into "less than pivot", "equal to pivot", and "greater than pivot" in a single partition pass, then recurses only on the less-than and greater-than sections. Benchmark it against your ordinary Lomuto quicksort from Part B on an array of 10,000 integers where every value is one of only 5 distinct numbers (heavy duplicates), and report both timings.
